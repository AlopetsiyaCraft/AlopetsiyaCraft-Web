# NeoForge: обработчик заказов магазина

Пример серверной части мода, которая забирает заказы сайта и выдаёт их игрокам.
Это не готовый мод, а каркас: скопируй классы в свой NeoForge-проект и подключи
тик-событие. Версия-зависимые места помечены комментариями.

## Как это работает

1. Раз в 30 секунд мод делает `GET /api/shop/orders/pending` с заголовком
   `x-api-key: <CHAT_API_KEY>`.
2. Для каждого заказа ищет игрока на сервере. Если игрок офлайн — заказ
   остаётся в очереди и будет забран на следующем опросе.
3. Выдаёт предмет/питомца/титул на главном потоке сервера.
4. Сообщает результат: `POST /api/shop/orders/result`
   `{ "orderId": 12, "ok": true }`.
   При `ok: false` сайт вернёт BLD игроку.

## Файлы

- `ShopConfig.java` — URL сайта, ключ, интервал опроса.
- `ShopOrderPoller.java` — HTTP-опрос, очередь, результат.
- `ShopOrderHandler.java` — выдача по `kind`.

## Подключение

В главном классе мода:

```java
@SubscribeEvent
public static void onServerTick(ServerTickEvent.Post event) {
    ShopOrderPoller.tick(event.getServer());
}
```

`ShopOrderPoller` сам считает тики и опрашивает сайт не чаще заданного
интервала. HTTP-запросы асинхронные, выдача — через `server.execute(...)`.

## Конфигурация

Переменные окружения (или замени на свой NeoForge config):

```bash
ALOPETSIYA_SHOP_URL=http://127.0.0.1:3000
CHAT_API_KEY=тот-же-ключ-что-в-.env-сайта
ALOPETSIYA_SHOP_POLL_SECONDS=30
```

Для продакшена — только HTTPS и ключ, который не попадает к клиентам.

## Формат заказа

```json
{
  "orders": [
    {
      "id": 12,
      "nickname": "Steve",
      "title": "Кастомный предмет",
      "kind": "item",
      "payload": {
        "material": "minecraft:diamond_sword",
        "name": "Клинок Алопеции",
        "lore": ["Выкован на сайте"],
        "enchants": { "minecraft:sharpness": 3 }
      },
      "createdAt": 1792705475000
    }
  ]
}
```

Поддерживаемые `kind`:

| kind | Что делает пример |
|---|---|
| `item` | выдаёт предмет с именем, лором и зачарованиями |
| `pet` | спавнит питомца с именем, приручает |
| `title` | сохраняет титул в `TitleStore` (интеграцию в чат добавь свою) |
| `nick_effect` | сохраняет эффект ника (интеграцию в чат добавь свою) |
| `cape` | **не обрабатывается автоматически** — заказ остаётся админу |
| `disc` | не из магазина; пропускается |

## Важно

- **Идемпотентность.** Сайт помечает заказ `delivered` только после ответа.
  Если ответ не дошёл, заказ может прийти снова. Веди локальный журнал
  выданных `orderId`, чтобы не выдать дважды.
- **Офлайн.** Не отмечай заказ выполненным, если игрока нет: он получит его
  при следующем входе.
- **Плащ.** Дизайн плаща согласуется вручную; пример намеренно оставляет
  `cape` в очереди, чтобы админ выдал его сам.
- **Безопасность.** Не логируй ключ. Не доверяй `payload` как коду: все
  ResourceLocation проверяются, размеры/числа ограничивай.
- **Версии.** API предметов и компонентов в 1.21.1 отличается от старых
  версий; если сборка не компилируется, поправь импорты `DataComponents`
  и `ItemEnchantments` под свою версию.

## Проверка вручную

```bash
KEY=$(grep '^CHAT_API_KEY=' .env | cut -d= -f2-)
curl -s -H "x-api-key: $KEY" http://localhost:3000/api/shop/orders/pending

curl -s -X POST -H "x-api-key: $KEY" -H 'Content-Type: application/json' \
  -d '{"orderId":12,"ok":true}' \
  http://localhost:3000/api/shop/orders/result
```
